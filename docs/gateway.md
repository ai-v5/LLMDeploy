# 多后端会话路由

`python -m deploy_gateway` 在本地 SSH 转发端口前提供兼容 OpenAI 的 HTTP/SSE 入口。健康后端按在途请求数、已绑定会话数分配新会话；已有会话优先保持同一机器，故障或容量不足时迁移并保持新绑定。绑定持久化，网关重启不主动重新分配。

```sh
python -m deploy_gateway --key-store local/gateway-keys.json --bindings-file local/session-bindings.json --backend-state local/backend-state.json
```

默认只监听 loopback，后端为本机 `19001`、`19002`，健康检查每两秒一次；失败立即摘除，连续两次健康检查通过后恢复参与分配。需要远程客户端时显式配置 `--listen` 和网络访问范围。升级网关前等待在途请求结束，保留旧程序及私有状态用于回退；不会操作远端 vLLM。

认证存储使用现有网关的 version 1 格式：`records` 中每项含 API key 的 SHA-256 `sha256` 和布尔值 `active`。所有客户端请求必须提供有效 Bearer key；Authorization 不转发给模型。认证存储、绑定文件、状态文件及其临时文件必须使用互不重叠的私有路径。这些运行文件均不得进入 Git，不提供含认证信息的示例配置。

客户端应传入稳定的会话头，优先级依次为 `x-session-affinity`、`x-deepseek-harness-session-id`、`x-session-id`；长度为 1–256 字符。缺少这些头时使用 `prompt_cache_key`，再缺少时使用第一条 user 消息作为近似会话标识。不同会话首条消息相同、历史压缩改变首条消息时，近似标识无法可靠区分会话，需显式会话头。绑定按认证 key 隔离，仅保存不可逆指纹和本地端口，不保存会话原文或请求内容。默认最多保存 16384 个会话；满额时拒绝新绑定，已有绑定继续工作，需要运维明确处理，不自动淘汰导致回迁。

连接失败或后端 5xx 时，仅在尚未向客户端发送响应头前尝试另一台。开始返回 SSE 后发生故障会结束该流，客户端可重新发起完整请求；无法搬迁正在生成的 KV 状态。网关不记录请求、响应或认证材料。慢请求的上游读取等待默认为 10800 秒，可用 `--upstream-timeout` 调整；它不是模型端的执行时限。

两台模型版本、图片和上下文限制应保持一致；上下文不一致时用 `--model-context-limit` 指定共同支持的下限。它保守收紧 `/v1/models` 的 `max_model_len` 声明，故障切换时也不把单台实验配置当作整个入口的能力。请求 token 校验仍由模型执行，不会静默截断输入。`backend-state.json` 的 `active_ports` 表示可用池，`active_port` 仅保留一个代表端口供旧消费者使用，不代表所有请求只在该端口执行。

需要给特定客户端开放长上下文时，为每个后端配置 `--backend-context-limit PORT=TOKENS`。客户端发送 `x-model-context-window`（总上下文 tokens，包含输出），只会使用支持该容量的健康后端，模型列表也按该请求的容量声明。缺少此头的客户端继续使用普通均衡与共同上限。没有符合容量的健康后端时返回 503，不降级到短上下文机器；会话迁移后保持新绑定。此头不转发给模型，实际请求仍由模型校验且不截断。只有一台支持长上下文时，该容量暂不具备双机故障切换能力。

DeepInfer 等自行调度 DP rank 的后端使用 `--backend-managed-affinity`：网关保留上述会话头和 `x-deepinfer-cache-namespace`，不注入 vLLM 的 `X-data-parallel-rank`。机器层绑定与原生 token 前缀缓存调度各自保留；机器故障或满载迁移后需要在新机器重新建立缓存。

重复 `--backend-port` 可配置任意数量的 loopback 后端，替代默认的两个端口。例如三个后端使用 `--backend-port 19001 --backend-port 19002 --backend-port 19008`。`--max-active-per-backend` 默认 32；全池同时等待上限由 `--max-waiting` 控制，默认 32，最长等待由 `--queue-timeout` 控制，默认 5 秒。选机和占用配额在同一把锁内完成；全池满载、队列满额或等待超时返回 429 和 `Retry-After: 1`，没有健康且准入的后端返回 503。该等待时限不包含模型执行时间。请求体最多 64 MiB，读取请求体也计入服务请求槽位；客户端断开时关闭对应上游连接并释放在途配额。

多个公开端口必须由同一个反向代理转发至同一网关进程，才能共享流控和会话绑定；不要为每个入口各启动一套网关。反向代理需保留 SSE 实时传输、客户端取消和认证头，关闭包含请求或认证材料的访问日志。可先启动一个新入口，验收后排空旧入口，再通过代理的平滑重载将旧端口作为别名加入。

TCP 监听队列为 256，用于吸收反向代理的瞬间建连，避免请求进入 HTTP 准入前被重置；它不扩大推理并发和等待配额。

可选 `--control-file local/admission.json` 支持滚动排空。文件内容为 `{"enabled_ports":[19001,19002,19008]}`，只准入列表内的已配置后端；采用临时文件加原子替换更新。空列表、文件缺失或无效内容会关闭新请求准入，现有流继续执行。健康探测循环刷新此控制，每轮结束后间隔两秒，`backend-state.json` 的各后端 `draining` 和 `inflight` 字段用于确认排空。只在配额、原生请求指标与客户端连接均排空后停止远端服务；保留旧容器与配方用于回退。

## 在既有入口增加模型别名

`python -m deploy_model_router` 在现有认证网关前增加 OpenAI 兼容模型别名。客户端仍使用既有 key；被选中的模型请求由路由器改写为上游真实模型名。有认证的上游使用 Windows 凭据管理器中的凭据，没有认证的上游不接收客户端 key。其他模型继续转发原网关，不混入原网关的健康池。上游地址、模型名称和凭据条目由操作者自行提供；凭据本身不放在命令、配置或日志中。

私有路由文件示例，地址均为占位回环端口：

```json
{"routes":[
  {"alias":"example-model","backend_model":"upstream-model","max_context":524288,
   "backends":[{"origin":"http://127.0.0.1:19030","credential_target":"LLMDeploy/example"}]},
  {"alias":"example-pool","backend_model":"pool-model","max_context":1048576,
   "backends":[{"origin":"http://127.0.0.1:19031"},{"origin":"http://127.0.0.1:19032"}]}
]}
```

```powershell
python -m deploy_model_router --listen 127.0.0.1 --port 19020 `
  --key-store local/keyring.json --fallback-origin http://127.0.0.1:19000 `
  --routes-file local/model-routes.json
```

路由器只接受 loopback 的原网关入口，不能将自身配置为回退入口。上游 origin 不含 `/v1` 路径。`GET /v1/models` 在原模型列表中增加配置的别名，实际模型名不作为新条目暴露；别名详情可通过 `/v1/models/<别名>` 查询。列表声明的是配置，不是上游健康证明。原网关不可用时，聚合列表只返回新增别名，原网关的健康检查应访问其独立入口，不能把聚合目录 200 当作原网关健康。`max_context` 是保守声明的输入与输出总上限，不代替模型端的 token 校验或实测。

同一别名的多个后端需要服务相同模型及兼容能力。会话优先保留实例；连接失败、429 或 5xx 时在响应开始前尝试同池其他实例，流开始后的失败不会重放当前请求，但后续请求会迁移。绑定保存在进程内，重启后重建。入口最多 256 个在途请求、单请求体最多 64 MiB、在途请求体总额最多 512 MiB；超出时返回 429。该额外上限可能使多条接近 64 MiB 的并发请求比原入口更早排队或被拒绝，部署前应评估现有工作负载。

前后使用两个反向代理时，须在接入前验证客户端 IP 的传递与可信代理设置，避免破坏用量统计；还须验证流式输出、客户端取消、原模型会话亲和、实际模型能力和上下游认证。改变入口可能影响正在运行的故障切换守护；不能仅重载代理，还须先核对并保持现有守护的配置及健康检查合同。命令只启动路由器，不切换现有入口。
